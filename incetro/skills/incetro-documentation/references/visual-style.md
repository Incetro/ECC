# Incetro Documentation – visual style

## Дизайн

GitHub-native, minimal, editorial. Акцент на иерархии, информативности и спокойной плотности информации.

- 1 заголовок H1 на странице, далее H2 и H3 последовательно.
- Обычные отступы между блоками вместо `---`, `***`, `___` и `<hr>`.
- Лаконичное вступление в 1–2 предложения.
- В программном проекте с подтверждённым стеком бейджи на первом экране README обязательны: обычно 3–6, максимум 6. Если доказаны лишь 1–2 технологии, добавляй 1–2 бейджа. В нетехнических репозиториях бейджи необязательны.
- Нет HTML-таблиц для декоративных колонок, нет искусственного центрирования всего README.
- Нет случайных эмодзи, крупных баннеров, псевдокарточек и emoji-маркеров в заголовках.
- Таблицы для сравнений и параметров. Текст для объяснений, списки для перечислений.
- Mermaid при реальном разветвлении и полезной архитектурной схеме. Не рисовать тривиальные цепочки.
- Заголовки содержательные: `Быстрый запуск`, `Архитектура`, `Настройка окружения` вместо `Всё, что нужно знать`.

## Цветовой код бейджей

Палитра **Incetro Balanced** утверждена как стандарт Incetro Documentation. Насыщенные цвета средней светлоты – выразительнее пастельных и легче прежних тёмных оттенков. Единая графитовая графика и сдержанная контрастность. Цвет выбирают по **смыслу**, а не по настроению автора. Изменение значений централизовано в этом файле.

| Категория | HEX | Применение |
| --- | --- | --- |
| Платформы и интеграции | `448FC7` | Telegram, iOS, Android, внешние платформы |
| Языки и runtime | `9170CF` | Python, Kotlin, Swift, Go, Node.js |
| Фреймворки | `34A494` | Django, Flutter, SwiftUI, Vue |
| Данные и хранение | `7587CF` | PostgreSQL, Redis, SQLite, S3 |
| Инфраструктура | `778EA5` | Docker, Terraform, hosting, deployment |
| Подтверждённый успех | `42A87A` | Реально успешная сборка или тест |
| Документация и лицензии | `8F9FB0` | Docs, MIT, Apache |
| Запланировано | `DCA052` | Не подключённая пока платформа |
| Ошибка или блокировка | `D56C7D` | Реально неуспешная сборка или blocker |

HEX без `#` в URL Shields.io. Фон левой части: `F5F7FB`. Цвет монохромного логотипа: `334155`. Не затемнять отдельные бейджи по вкусу автора. Добавлять новые цвета только при необходимости нового семантического статуса.

## Формат Shields.io

Бейджи выполнены как 2-тоновая система умеренной насыщенности. Левая часть – единый нейтральный фон `labelColor=F5F7FB` (почти белый), правая часть – насыщенный цвет средней светлоты по категории. Везде `style=flat-square`. Для монохромных логотипов используется `logoColor=334155` (графитовый). Внутренний текст должен оставаться читаемым в обеих темах GitHub. Ссылку с бейджа направлять к релевантному источнику: workflow, инструкциям, реализации или официальной технологии.

Пример формы, **не готовое утверждение о произвольном проекте**:

```md
![Python](https://img.shields.io/badge/Python-3.12%2B-9170CF?style=flat-square&labelColor=F5F7FB&logo=python&logoColor=334155)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-16-7587CF?style=flat-square&labelColor=F5F7FB&logo=postgresql&logoColor=334155)
![Docker](https://img.shields.io/badge/Docker-Compose-778EA5?style=flat-square&labelColor=F5F7FB&logo=docker&logoColor=334155)
```

Версии сверять с манифестом проекта. Отсутствие бейджей при подтверждённом стеке – ошибка. `check-docs.js` требует минимально 1–3 бейджа по независимым признакам стека, а агент проверяет содержание, версии, семантику цветов и оформление 3–6 бейджей. Не путать заявленную поддержку, реализованную интеграцию, тестовое покрытие и успешный продакшен-деплой.

### Статусы

- `passing` – только динамический GitHub Actions/CI badge, связанный с существующим workflow, либо подтверждённая внешняя система.
- `coverage` – только при реальном отчёте покрытия; не вычислять по наличию тестов.
- `release` – только из реальных тегов/релизов.
- `license` – только при наличии корректного лицензирующего файла или явно заданной лицензии.
- `planned` – только если информация о планах действительно помогает. Не украшать первый экран десятком дорожных карт.

## Текст и типографика

Пунктуационное тире – `–` с пробелами; диапазон `1–3` без пробелов; дефис в `Telegram-бот`. Не использовать `—`. Числа цифрами. Технические имена и команды сохраняют исходный синтаксис. Ключевые инструкции не прячутся в `<details>`.

## Предпросмотр

Проверяй README непосредственно в GitHub Markdown или совместимом preview. Убедись, что рендеринг одинаково удобен в светлой и тёмной темах. Внешние SVG и бейджи не должны быть критичны для понимания без изображения.
