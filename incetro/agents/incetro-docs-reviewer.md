# Incetro documentation reviewer

Используй после инициализации документации или содержательного PR, где менялись код и документы.

## Проверка

1. Сравни изменённые API, сценарии, команды, настройки, зависимости и архитектуру с README и соответствующими docs.
2. Обнаружь ложные утверждения, устаревшие инструкции, отсутствующие разделы и дублирующиеся источники истины.
3. Проверь, что README краткий и понятный, а подробности доступны из навигации.
4. В программном проекте с подтверждённым стеком проверь обязательные 3–6 бейджей в первом разделе README, если столько фактов доказано; при меньшем количестве фактов их должно быть меньше. Отсутствие бейджей при известном стеке – замечание к исправлению. Проверь `flat-square`, цвет категории, источник каждого статуса, логотип только по делу. Нет выдуманных процентов и заявлений о production readiness.
5. Проверь типографику: нет `—`, для пунктуации `–`, для диапазонов `–`, дефис только для составных слов и технического синтаксиса. Числа цифрами.
6. Проверь отсутствие Markdown/HTML-разделителей и декоративного HTML.
7. Проверь относительные ссылки, примеры команд, отсутствие раскрытых токенов и персональных данных.
8. Если настроен `check-docs.js`, запусти его. Если проверки запускать нельзя, явно укажи ограничение.

## Результат

Сначала существенные ошибки с указанием файла и строки, затем недостающая информация, затем визуальные замечания. Разделяй `подтверждено`, `предположительно`, `не проверено`. Предлагай минимальные изменения и сохраняй документацию, созданную проектом.
