# Документация проектов Incetro

Incetro ECC поставляет стандарт живой документации для Cursor. Главный README проекта остаётся краткой точкой входа. Технические детали находятся в канонических документах, организованных по смыслу.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `incetro-documentation.mdc` | Всегда применяемое правило проверять docs при содержательных изменениях |
| `incetro-documentation` | Skill первоначального аудита, создания и постоянного обновления |
| `incetro-docs-reviewer` | Независимая проверка достоверности, полноты, эстетики и навигации |
| `scripts/check-docs.js` | Локальная проверка базовых структурных ошибок |
| `references/visual-style.md` | Палитра семантических цветов и стиль `flat-square` |
| `templates/docs-quality.yml` | Опциональный GitHub Actions workflow для проектов |

Компоненты включены в `core` и наследуются остальными профилями. Существующий upstream skill `living-docs-governance` дополняет методологию, а не дублируется.

## Использование

После установки в проект:

```bash
incetro-ecc update
node .cursor/skills/incetro-documentation/scripts/check-docs.js
```

Для старого проекта запусти skill `incetro-documentation` с задачей инвентаризации и приведения документации к стандарту. После изменения функциональности правило просит агента обновлять затронутые разделы вместе с кодом. Отдельный агент проверки вызывается явным поручением или активной оркестрацией проекта.

## Реальные границы автоматизации

- Установщик не меняет `README.md`, `docs/**` и `.github/workflows/**` проекта.
- Правило `alwaysApply` задаёт постоянные инструкции Cursor, не является системным post-commit hook.
- GitHub Actions не включается до добавления workflow в проект. Инструкция – `incetro/skills/incetro-documentation/references/ci.md`.
- Проверка скриптом выявляет ошибки оформления и простых относительных ссылок, не доказывает истинность бизнес-описаний.
- Существующая документация может потребовать однократной очистки перед включением CI.

## Типографика и эстетика

В документах отсутствуют декоративные горизонтальные разделители. Русская пунктуация использует `–`, дефис `-` внутри слов и `–` для диапазонов. Длинное тире `—` запрещено в обычном тексте; технический синтаксис сохраняется. Все бейджи Shields.io имеют `style=flat-square`, общий светлый фон слева `F5F7FB`, графитовые логотипы `334155` и насыщенный цвет средней светлоты по семантической категории из палитры Incetro Balanced.

Палитра Incetro Balanced утверждена. Изменения цветов делаются в `references/visual-style.md` без переписывания архитектуры.
